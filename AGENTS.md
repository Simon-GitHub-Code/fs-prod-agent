# Agent contract

`tests/fitness` is the authority for structure. `tests/unit` checks one module. `tests/integration` runs `build("local")`. Where this file and a green test disagree, the test wins. Fix the production code. Do not weaken a test, raise the complexity ratchet, lower an eval baseline, or add a tool whose name describes an order, a trade, a payment, or an email.

## Authority order

1. A green guard in `tests/fitness` or a pinned eval baseline.
2. This file. `CLAUDE.md` imports it and nothing else.
3. The question contracts in `decisions/v1/` and the tool manifests in `mcp_servers/catalog.py`.
4. Local code conventions.
5. The issue, ticket, or prompt.

A lower entry never overrides a higher one by accident. When a request conflicts with a higher entry, stop and say which one has to change.

## Where code goes

- `domain/` holds the desk's numbers. It does not import ports, decisions, or adapters.
- `decisions/v1/` is the question text. Editing an instruction fails the snapshot. Add `decisions/v2/` instead.
- `policy/` returns approve, review, reject, failed, or uncertain. A model signal does not grant permission.
- `application/` runs the pipeline. It does not import adapters. Policy admits a route, and only an approved workflow or agent starts a runner.
- `composition.py` is the only module that wires adapters. `build("local")` is the profile that runs. `build("aws")` stays unconfigured.
- Tools are names on manifests in `mcp_servers/catalog.py`. The gateway is the only caller. `adapters/local/mcp_tools.py` serves them over MCP, and `adapters/local/gateway_mcp.py` is the gateway: in-process by default, or a Streamable HTTP URL.
- Eval cases live in `/evals`. The loader is `fs_prod_agent.evals`. The routing suite is `evals/routing/v1/cases.jsonl`, scored by `fs_prod_agent.evals.score`.

## Gate

`scripts/verify` runs ruff and the fitness, unit, and integration suites. Pre-commit runs that command. Pre-push runs `scripts/secrets`. GitHub Actions runs verify, the secret scan, and `scripts/mutate`. That command runs mutmut on `domain/oversight.py`, `policy/authorize.py`, and `decisions/contract.py`, and it fails when a mutant survives or no test runs it. Hooks can be skipped, so CI is the floor. Do not pass `--no-verify` or disable a hook unless the user names it.

In Claude Code, `scripts/context/hooks/pre_push_gate.py` refuses a `git push` while `scripts/verify` is red. In Grok, a `Stop` hook runs `scripts/verify` at the end of a turn.

The files named in `scripts/guardpin.py` are hash-pinned, including this file and `tests/fitness/`. Unit tests and integration tests are not. `tests/fitness/test_guard_integrity.py` fails when a pinned file changes. `.grok/hooks/approval.py` asks before a write to a pinned file, in both agents. `scripts/bless` records the change only when every moved path is named and the verdict is `--caught` or `--routine`.

## Evals

`tests/integration/test_routing_evals.py` runs the 78-case routing suite through `build("local")` on every change and fails when it regresses past `evals/baselines/fixture.json`. An unsafe approval is a run that policy approved when the label says a person, a refusal, or a rejection. `scripts/evals --model gpt-oss:120b` scores the live stack and writes `evals/reports/`. A live baseline allows no unsafe approvals. `evals/baselines/` is hash-pinned.

## Context pack

`docs/context/` and `.grok/rules/context-pack.md` are generated by `scripts/context/build.py`. `tests/fitness/test_context_pack.py` byte-compares both, so a hand edit cannot match. Ask the pack before you grep: `uv run python scripts/context/query.py layer <path>`, `who-imports <module>`, `hotspots`, `guards`.

In Claude Code, `scripts/context/hooks/session_start.py` injects `docs/context/index.md` when a session or a subagent starts, with two health lines: whether the complexity hook answers and whether the git hooks are installed. A line that says DEAD names what to fix. `scripts/context/hooks/post_edit_complexity.py` rebuilds the pack after an edit to production code and is silent unless a function is over the cap, which it names in the same turn. A file written through Bash gets no answer, so run `query.py layer` yourself.

In Grok, `.grok/rules/context-pack.md` loads at session start, and `.grok/hooks/context_pack.py` returns it when an edit changes it.

Cyclomatic scores come from `scripts/context/lib/complexity.py`. New functions stay at 10 or under. `validate_decision` and `authorize` are named exceptions because they are the decision tables. CRAP is not in this repo.

## Stop and ask

Stop and ask before a change that would:

- weaken, edit, or bypass a guard, the complexity ratchet, an eval baseline, a hash pin, or a CI step;
- change a question in `decisions/v1/`, a tool's effect in the catalog, or what policy returns for a mutating tool;
- add a layer, a port, or an import that crosses a boundary the fitness suite names.

Do not ask about routine implementation that touches none of these.

## Reporting completion

Say that no guard was weakened, no hook was bypassed, and no baseline was lowered, and name any bless. Say what validation actually ran, what did not, and anything that degraded. Then summarise the change.
